# QWB-003 长周期计划同步与当日批量口径

> **需求编号**: QWB-003
> **创建日期**: 2026-09-10
> **状态**: 已完成

---

## 1. 需求背景

跑批计划目前只能在维护页面上一条条登记，而实际的计划来源是导出的表格
`UAT2主环境及长周期批量计划.xlsx`：一个工作表就是一个环境的跑批日历，长周期一天最多 3 个批
（例如 09-11 的 10:30 / 15:30 / 19:00），每批各自记录“系统当前会计日期 → 跑批后会计日期”。
现状有三个问题：

1. **计划没有同步入口**：表格里 50 多条长周期批次只能手工录入，改一次计划就要重录一次。
2. **通知粒度和批量粒度不匹配**：跑批页的“开始/完成”按钮每点一次就往默认机器人推一条消息
   （“开始”还会 `@所有人`）。一天 3 个批就是 6 条通知，群里全是噪声，而大家真正想知道的只有
   “今天哪几个时间点要跑批”和“今天跑完系统日期到哪天”。
3. **消息里的交易日取数会跑偏**：`{current_trading_date}` / `{next_trading_date}` 取的是
   “最早一条未完成的计划”，一旦导入跨月的长周期计划，历史批次没点“完成”就会把消息里的
   日期一直钉在过去（例如 09-10 的消息显示 2026-07-01 → 2026-07-21）。

**目标**：把表格里的长周期计划一次性同步进跑批计划；消息侧改成**当日口径**——一天多批也只播报
“当日批开始时间 + 当日批后会计日期”，逐个批的即时通知默认关闭但可开关。

## 2. 改造范围

### 1. 跑批计划表格同步（`import-plan`）

**实现逻辑：**
- 新增 `qwbot/xlsx.py`：只用标准库解析 `.xlsx`（`zipfile` + `ElementTree`），支持共享字符串、
  内联字符串、多工作表，并按 `styles.xml` 的 `numFmt` 把 Excel 序列号还原成日期/时间文本。
- 新增 `qwbot/plan_import.py`：按表头把一行映射成 `batch_plan` 字段，再按业务主键 upsert 进库。
- `qwbot/cli.py` 新增 `import-plan` 子命令：

```sh
python -m qwbot.cli import-plan tmp/UAT2主环境及长周期批量计划.xlsx           # 默认长周期、跳过历史
python -m qwbot.cli import-plan 计划.xlsx --sheet 长周期 --dry-run            # 预演
python -m qwbot.cli import-plan 计划.xlsx --past archive --today 2026-09-10   # 历史批次按已归档写入
```

- 导入完成后直接打印当日口径（批开始时间、批后会计日期），不用再去页面上核对。

**关键设计：**
- **业务主键 =「分类 + 自然日历 + 跑批启动时间」**。重复导入只覆盖计划字段
  （日期、时间、说明、分类），页面上点过的 `execution_status` / `started_at` / `completed_at` /
  `execution_seconds` / 阻塞记录原样保留，所以“表格更新后重跑一次”是安全操作。
- **默认只导入今天及以后的批次**（`--past skip`）。页面上的执行权限是严格串行的
  （只有最早一条“待执行”能点“开始”），历史批次若以“待执行”留在未归档列表，会把今天开始的
  所有操作全挡住。需要保留历史时用 `--past archive`，按“已完成 + 已归档”写进归档记录。
- **小组备注并进“说明”**：`计结息专项`、`流程作业组（零售）`、`资信评级组` 等列不是计划字段，
  但里面是“批前数据准备/批后验证/加批场景”这类关键信息，按 `列名：内容` 追加到 `description`
  的后续行（`.description-cell` 本来就是 `pre-wrap`，页面上按多行展示）；`content` 只留
  `跑批说明` 一行，通知和明细里引用的都是这一行。
- **源表的“节假日标志”不写进 `holiday_flag`**：核对源数据后确认该标志说的是**批后会计日期**
  落在节假日（如 09-11 15:30 批后是 09-25 中秋），而 QWBot 的 `holiday_flag` 表示
  **自然日是节假日**并被 `is_holiday()` 用来跳过当天的提醒。直接照搬会让 15 个左右正常工作日
  被误判成节假日、当天所有 `business_day` 模板静默不发。默认把它记成说明里的一行
  “批后会计日期为节假日”，确实要按源表写入时加 `--keep-source-holiday-flag`。
- 只覆盖长周期：`--sheet` 默认 `长周期`，`--category` 默认取工作表名。UAT2 主环境后续用
  `--sheet UAT2` 同一套逻辑导入，分类不同因此主键不会互相覆盖。

**文件改动：**
- `qwbot/xlsx.py`: 新增，标准库 `.xlsx` 读取器（工作表列表、单元格取值、日期/时间格式识别）
- `qwbot/plan_import.py`: 新增，表头映射、说明合并、业务主键 upsert、`ImportSummary` 报告
- `qwbot/cli.py`: 新增 `import-plan` 子命令及 `--sheet/--category/--past/--today/--dry-run/--keep-source-holiday-flag`
- `tests/test_plan_import.py`: 新增，自带一个最小 `.xlsx` 写入器，不依赖 `tmp/` 里的真实文件

### 2. 当日批量口径与消息变量

**实现逻辑：**
- `qwbot/planner.py` 新增 `daily_batch_context(items, today)`，一次算出当天的全部口径：

| 变量 | 含义 | 当天有批 | 当天没有批 |
| --- | --- | --- | --- |
| `{today_batch_start_times}` | 当日批开始时间 | 全部批次时间，`、`分隔 | `无` |
| `{today_post_batch_date}` | 当日批后会计日期 | 最后一批的 `next_accounting_date` | `无` |
| `{today_batch_detail}` | 当日批量明细 | 每批一行：`10:30 存量特殊日期（2026-09-22 → 2026-09-24）` | `无` |
| `{current_trading_date}` | 当前交易日 | 第一批的 `current_accounting_date` | 上一批的批后会计日期 |
| `{next_trading_date}` | 下一交易日 | 最后一批的批后会计日期 | 下一个待执行批量的批后会计日期 |

- `qwbot/message.py` 的 `build_template_variables()` / `render_message_template()` 增加
  `batch_plan` 入参：传了就按当日口径取数，不传时沿用原来“单个 `next_batch`”的口径
  （CLI 老调用方和现有测试不受影响）。
- 调用方（`cli.py` 的 `preview` / `send-now` / 定时派发，`web.py` 的模板预览和“测试发送”）
  统一改成把整份 `payload["batch_plan"]` 传进去，`_next_active_batch()` 随之删除。
- `store.py` 的 `REMINDER_TEMPLATE_VARS` 增加三个新变量（模板编辑器里可点击插入），
  `DEFAULT_REMINDER_TEMPLATE` 增加“当日批开始时间/当日批后会计日期”两行；
  `static/app.js` 的预览兜底值同步补齐。

**关键设计：**
- **“下一批”只看今天及以后**：`_upcoming_batch()` 过滤 `natural_date >= today` 且未完成，
  没执行完的历史批次不会再把消息里的交易日拉回过去。
- **当天没有批时的“当前交易日”取上一批的批后日期，并且包含已归档记录**：昨天的批今天凌晨
  就自动归档了，若只看未归档记录，非跑批日的消息会显示“无”。
- **当天已完成的批仍然算当天口径**：18:00 的提醒要能说清“今天跑完了、系统日期已经到 X”，
  所以 `today_batch_*` 不按执行状态过滤，只有 `next_batch` 过滤未完成。

**文件改动：**
- `qwbot/planner.py`: 新增 `DailyBatchContext` / `daily_batch_context()` / `short_description()`
- `qwbot/message.py`: 变量构建支持 `batch_plan`，新增三个当日变量
- `qwbot/store.py`: `REMINDER_TEMPLATE_VARS`、`DEFAULT_REMINDER_TEMPLATE`
- `qwbot/cli.py`、`qwbot/web.py`: 渲染时传整份计划，删除 `_next_active_batch()`
- `qwbot/static/app.js`: 预览兜底变量
- `tests/test_daily_batch_variables.py`: 新增，覆盖多批/无批/已归档/历史残留/空计划

### 3. 批量即时通知改为可开关，默认关闭

**实现逻辑：**
- `store.py` 新增 `app_settings` 读写（`get_app_setting` / `set_app_setting`）和
  `batch_event_notify_enabled()` / `set_batch_event_notify()`，开关键 `batch_event_notify`，默认 `false`。
- `web.py` 的 `start_item` / `complete_item` 只在开关打开时才调用 `_send_batch_notice()`；
  状态流转、执行时长、阻塞记录和自动归档逻辑完全不变。
- 新增 `POST /batch-event-notify`，在 `/notifications` 页面的“批量即时通知”卡片上一键开关，
  和其他消息配置一样存库、立即生效、不需要重启容器。
- 跑批页“开始/完成”的确认文案跟着开关变：关闭时提示“不会推送消息”，避免误以为已经通知过群里。

**关键设计：**
- 用数据库开关而不是 `.env`：QWB-002 之后消息相关配置都在页面上维护，`.env` 改了还要重启容器。
- 默认关闭而不是直接删掉推送代码：单个批的环境（如主环境一天一批）仍然可能需要即时通知，
  开关保留能力，长周期这类一天多批的环境关掉即可。

**文件改动：**
- `qwbot/store.py`: `app_settings` 读写 + 开关函数
- `qwbot/web.py`: `start_item` / `complete_item` 加开关判断，新增 `update_batch_event_notify` 路由
- `qwbot/templates/_notification_section.html`: 新增“批量即时通知”卡片
- `qwbot/templates/_batch_section.html`: 确认文案随开关变化
- `qwbot/static/style.css`: 卡片内开关和说明文字样式
- `tests/test_web_routes.py`: 拆成“默认不推送”和“开启后推送到默认机器人”两个用例

## 3. 技术细节

#### 不装 openpyxl 也能读导出表格

导出文件的 `styles.xml` 会让 openpyxl 直接抛 `TypeError: Fill() takes no arguments`，
装依赖也读不出来。`qwbot/xlsx.py` 按 OOXML 结构自己解析：

1. `xl/workbook.xml` + `xl/_rels/workbook.xml.rels` 拿到工作表名和分片路径；
2. `xl/sharedStrings.xml` 还原共享字符串，`t="inlineStr"` 走内联字符串分支；
3. `xl/styles.xml` 里 `cellXfs[s] -> numFmtId -> formatCode`，按内置 ID（14~17、27~36、45~47 等）
   和自定义格式码（去掉 `[$-F800]`、引号字面量、转义符后看 `y/d` 与 `h/s`）判定日期/时间/日期时间；
4. 序列号按 1900 日期系统还原（纪元 `1899-12-30`，`23:59:59.6` 这类进位单独处理）。

`styles.xml` 读不出来时只是不做日期转换，不会让整个导入失败。

#### 表格大小上限（SEC-02）

`.xlsx` 是 zip，压缩比可以很高。读取前会先按目录项里记录的**解压后**大小做预算校验，
超过 `64 MiB` 直接拒绝（真实多年期表格通常只有几百 KB），加密分片同样拒绝；单个工作表
还有行数/列数上限（`200000` 行、`16384` 列），工作表内容按行流式解析，超限的表格在解析
中途就报错，不会把整棵树搬进内存。CLI 侧表现为一条 `XlsxError` 提示，退出码非零。

#### 表头识别

表头做了两层归一化：去掉所有空白（`系统当前\n会计日期` → `系统当前会计日期`）、全角括号转半角，
再按“等于或以别名开头”匹配，所以 `跑批说明` / `说明`、`节假日标志` / `节假日标志Y-是/N-否` 都能识别。
`序号`、`星期` 直接忽略，`利率变更标识` 只在 `Y` 时记一行“利率变更”，其余未知列一律作为
`列名：内容` 追加进说明，表格加列不需要改代码。

#### 当日口径的取数顺序

```
今天有批 → current = 第一批.current_accounting_date
           post    = 最后一批.next_accounting_date
           next    = post
今天没批 → carried = max(natural_date < today 的所有行，含已归档).next_accounting_date
           current = post = carried
           next    = 下一个未完成批次(natural_date >= today).next_accounting_date or carried
```

长周期实测：09-11 两批 → `10:30、15:30`，批后 `2026-09-25`；09-13 不跑批 → 当前/批后都停在
`2026-09-30`（09-12 最后一批的结果），下一交易日是 09-14 那批的 `2026-10-09`。

## 5. 测试要点

1. 导入长周期：54 行表格 → 32 条今天及以后的计划，22 条历史按 `--past skip` 跳过；重复导入 0 新增。
2. 重复导入不冲掉执行态：手工把某批改成“进行中”并写了 `started_at`，再导入一次，状态和时间保留、说明以表格为准。
3. `--past archive`：历史批次落成“已完成 + 已归档”，`completed_on` 是自然日、`archived_on` 是今天。
4. 日期/时间解析：序列号 → `2026-09-10`，日分数 → `15:00`，跨行表头正常识别。
5. 说明合并：`计结息专项`、小组列、`利率变更标识=Y`、源表节假日标志都出现在说明的后续行，`content` 只有一行。
6. 当日口径：一天 3 批时 `{today_batch_start_times}` 是 `10:30、15:30、19:00`、`{today_post_batch_date}` 是最后一批的批后日期；
   当天没有批时两者为 `无`、`{current_trading_date}` 取上一批（含已归档）的批后日期。
7. 历史残留不影响当天：留一条 08-12 的“待执行”计划，今天的消息日期仍然是今天的口径。
8. 即时通知开关：默认点“开始/完成”不发任何 webhook；打开开关后照旧发到默认机器人并 `@所有人`；跑批页确认文案随开关变化。
9. 旧库升级：`webhooks(env/enabled)` + `template_schedules(weekdays/legacy_id, FK→reminder_templates)` 的库打开后
   机器人、模板、通知时间、文档链接变量齐全，`template_schedules` 外键指向 `message_templates`；健康库重复 `init_store` 无变化。
10. 回归：`python -m pytest -q` 全绿（116 项），`python -m qwbot.cli preview` 输出的交易日与计划一致。
